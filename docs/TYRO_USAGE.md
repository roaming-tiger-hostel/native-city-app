# Native City · Tyro 사용법

**캐릭터 선택 → 옵션 답변 → 추천 장소 선택 → 하단 지도.**
추천에는 캐릭터와 취향을 가르친 사람을 표시합니다. LLM은 **Qwen**입니다. 키가 없으면 같은 후보·옵션을 규칙 엔진으로 체험할 수 있습니다.

## 1. 실행

Node.js 22.15 이상(24 권장), pnpm 10.33.2 기준입니다.

```bash
pnpm install --frozen-lockfile
pnpm dev
```

브라우저에서 `http://localhost:3000`을 엽니다. `/guest`도 같은 화면입니다. 로그인 없이 체험 가능합니다.

- **마야**: 돼지고기 없는 점심 / 밤 11시 야식.
- **톰**: 가성비 좋은 저녁.
- **유키**: 첫 서울 점심.
- **누리**: 호스텔 근처의 음식·산책.
- **소리**: 별점보다 음식 취향.
- **달**: 조용한 산책·비 오는 날.

화면 상단 `EN` / `한국어`로 언어를 바꿉니다. 기존 대화 문장을 번역하지는 않으며, 이후 답변 언어가 바뀝니다.

## 2. Qwen 키 넣기 — 권장: `.env.local`

프로젝트 루트에 `.env.local`을 만들고 다음을 넣습니다. 실제 키는 이 파일에만 입력합니다.

```dotenv
QWEN_API_KEY=여기에_본인의_DashScope_API_키
LLM_BASE_URL=https://dashscope-intl.aliyuncs.com/compatible-mode/v1
LLM_MODEL=qwen-plus
```

개발 서버를 껐다가 `pnpm dev`로 다시 시작합니다.

- 키 이름은 **비어 있지 않은 값** 기준 `LLM_API_KEY` → `QWEN_API_KEY` → `DASHSCOPE_API_KEY` → 기존 `OPENROUTER_API_KEY` 순서입니다. 하나만 설정하는 편이 명확합니다.
- 위 URL은 기존 국제 DashScope 기본값입니다. 발급한 키의 지역과 엔드포인트가 일치해야 합니다. 다른 지역은 해당 콘솔의 OpenAI-compatible base URL을 `LLM_BASE_URL`로 설정합니다.
- URL 끝에 `/chat/completions`를 직접 붙이지 않습니다. 서버가 붙입니다.
- 기본 모델은 `qwen-plus`; 계정에서 사용 가능한 Qwen 모델로 `LLM_MODEL`을 바꿀 수 있습니다.
- `NEXT_PUBLIC_` 접두사를 쓰지 않습니다. 키는 서버에서만 읽습니다.
- `.env.local`과 `data/runtime/*.json`은 Git에서 제외됩니다. 키를 채팅·스크린샷·커밋에 넣지 않습니다.

지역별 URL과 모델 권한은 [Alibaba Cloud 공식 OpenAI 호환 안내](https://www.alibabacloud.com/help/en/model-studio/compatibility-of-openai-with-dashscope)를 확인합니다.

### 화면에서 설정

로컬 `/studio` → **장소 / Places** → **Qwen / LLM 키**에 붙여 넣고 저장할 수도 있습니다. 기본 국제 DashScope URL과 Qwen 모델을 사용합니다. 다른 지역·모델은 위 환경변수 방식이 명확합니다.

스튜디오 저장은 `.env.local`과 `data/runtime/secrets.json`에 기록합니다. 재시작 후 환경변수로 읽힌 키는 화면에서 잠깁니다. 변경하려면 해당 환경변수를 수정하고 재시작합니다. 환경변수로만 넣은 키는 그 값을 지우고 재시작하면 제거됩니다. 스튜디오로 저장했던 키는 파일에도 남아 있으므로, `.env.local`의 키를 비우고 재시작한 뒤 스튜디오의 **키 지우기**도 눌러야 완전히 제거됩니다. 서버리스의 화면 저장 키는 일시적이므로, 배포 환경에서는 호스팅 서비스의 환경변수를 사용합니다.

## 3. 2분 데모

1. 홈에서 **마야**를 누릅니다.
2. **밤 11시, 돼지고기 없는 야식** 옵션을 누릅니다. 직접 입력하지 않아도 됩니다.
3. 답변 아래 **추천 장소 옵션**을 누릅니다. 선택도 `/api/chat`을 거쳐 Qwen/규칙 엔진이 확인해 줍니다.
4. 하단 지도에 해당 장소가 남습니다. 핀을 누르면 추천 이유·주소·정보 출처가 보입니다.
5. **좋아요 / 내 취향은 아냐**를 누릅니다. `/studio` → 손님 대화에서 피드백을 확인합니다.
6. 목록으로 돌아가 **달**과 대화하면 다른 범위와 취향의 추천을 비교할 수 있습니다.

지도와 대화 사이 손잡이를 위아래로 움직여 높이를 바꿉니다. 키보드로 손잡이에 포커스한 뒤 위·아래 화살표도 가능합니다. 작은 화면에서는 장소 정보를 직접 열 때만 하단 패널이 뜹니다.

### Qwen이 실제로 답했는지

- **Qwen 준비됨**: 키가 설정됐다는 뜻이며, 실제 연결 성공 표시는 아닙니다.
- 답변에 **Qwen**: 이번 응답이 Qwen에서 왔고 기본 검사를 통과했습니다.
- 답변에 **규칙 답변**: 키가 없거나, 요청 실패·시간 초과·내용 검사 실패로 폴백했습니다.

Qwen 요청은 12초 제한입니다. 엔진의 추천 후보와 순서를 넘기고, 후보 외 장소가 섞이거나 1순위 이름이 없는 답변은 폴백합니다. 이는 완전한 사실 검증기는 아닙니다. 후보가 없으면 Qwen 호출 없이 조건에 맞는 장소가 없다고 답합니다.

인증·지역·모델 오류가 있어도 규칙 데모는 계속 동작합니다. 개발자 도구 Network의 `/api/chat` 응답에서 `voice`, `llm.configured`, `llm.model`로 구분할 수 있습니다. 서버 응답에는 키 전문이 포함되지 않습니다.

## 4. 피드백과 학습

- 좋아요/아쉬워요는 해당 답변에 연결해 저장하며, 자동으로 전역 취향 가중치를 바꾸지 않습니다.
- 트레이너는 `/studio`에서 손님 대화를 보고 추천을 교정하거나 A/B 장소 판정을 합니다.
- 기존 판정 엔진의 가중치·판정 기록이 다음 추천 순위에 반영됩니다. Qwen은 확정된 후보를 캐릭터의 말투로 설명합니다.
- 최근 대화 최대 40개, 각 대화 최근 40문장을 보관합니다. 대화 옵션과 추천자 정보도 복원합니다.
- 현재는 데모용 로컬 파일과 브라우저 저장소입니다. 다중 사용자 인증·DB 격리는 아직 없습니다.

## 5. 장소 데이터와 지도

TourAPI 키는 선택 사항입니다. `TOUR_API_KEY`를 `.env.local`에 넣으면 기존 TourAPI 조회를 사용합니다. 없으면 시드 카탈로그를 사용합니다. 지도 배경은 OpenStreetMap 타일이라 인터넷 연결이 필요합니다.

시드 장소·취향·손님 수는 **데모 데이터**입니다. 현재 영업, 할랄 인증, 재료·교차 조리 안전성을 보증하지 않습니다. 돼지고기/채식/늦은 시간 조건은 명시된 태그가 맞는 후보만 통과시키며, 빈 결과일 때 제외한 장소를 다시 넣지 않습니다. 대화의 조건을 풀고 싶으면 **새 대화**를 시작합니다.

Qwen은 추천 후보 선택을 대신하지 않습니다. 사용자 조건·캐릭터 범위·판정 엔진이 후보를 고르고 Qwen이 설명합니다. 액티비티 커머스는 정보 패널의 “준비 중” 자리만 있으며 예약·결제는 연결하지 않았습니다.

## 6. 확인 명령

```bash
pnpm test
pnpm lint
pnpm build
```

`pnpm test`는 별도 테스트 패키지 없이 Node 테스트 러너를 사용합니다. Qwen 테스트는 **모의 응답**으로 통신 형식과 폴백을 확인하며, 실제 DashScope 과금 호출은 하지 않습니다. 임시 디렉터리에서 실행해 실제 키·대화 파일을 변경하지 않습니다.

2026-09-19 작업 환경의 실행 검증·제약은 [검증 기록](TYRO_VERIFICATION.md)에 기록합니다.

## 남은 빚

- 실제 키로 DashScope 응답을 확인하는 통합 스모크 테스트.
- 실사용자용 인증, 키 관리 API 보호, 요청 제한, 사용자별 영속 DB.
- 장소 정보의 신선도와 출처를 필드 단위로 추적하고 식이 조건의 실정보 검증.
- 피드백 이력 전체 보존, 트레이너 승인 과정, 지속적인 평가 데이터.
- 액티비티 제휴·예약·결제는 이후 범위.
