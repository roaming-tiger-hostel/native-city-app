## 1. 서비스 소개
### ① 서비스명
Native City

### ② 서비스 유형
웹

### ③ 서비스 개요
서울을 방문한 여행자가 문화·식사 제약·여행 취향에 맞는 AI 친구와 대화하며, 한국관광공사 TourAPI가 제공하는 장소 정보를 근거로 추천을 받는 웹 서비스입니다. 게스트는 `/guest`에서 캐릭터를 고르고 옵션·자유 입력·답 칩으로 대화하며, 호스트는 `/studio`에서 취향을 보강합니다.

### ④ 주제 선정 이유
리뷰·평점은 넘치지만 “누구의 취향으로 믿을지”가 불명확합니다. Native City는 불특정 절대값이 아니라 **특정 네이티브/호스트 취향에 귀속된 추천**을 대화로 제공하고, 장소의 명칭·주소·좌표 등 사실은 공사 OpenAPI로 근거를 남깁니다.

### ⑤ 서비스 핵심기능
1. AI 친구 선택·대화(옵션/자유입력/답 칩)
2. 취향·식이 제약 반영 장소 추천 카드
3. 지도·주소·TourAPI 출처 표시
4. 호스트 스튜디오(취향 A/B·장소 동기화)
5. 심사/상태 안내(`/submit`)

### ⑥ 서비스 대표 이미지(1장)
→ `/guest` 캐릭터 선택 또는 채팅+지도 화면 캡처 1장 (Tyro 촬영)

### ⑦ 서비스 상세 이미지(3~5장)
권장: (1) 채팅+답칩 (2) 장소 옵션 카드 (3) 지도/출처 (4) 스튜디오 (5) `/submit` TourAPI 상태

## 2. [선택] 지역 특화 — **해당 없음(선택 생략 가능)**
데모 범위는 서울(중구 무학동 인근)이나, 공고상 지역특화는 **서울 제외**이므로 본 항목은 비우거나 “해당 없음”으로 둔다.

## 3. 서비스 핵심 기능별 흐름도
### ① 핵심 기능명 및 설명(최대 5)
1. 캐릭터 대화: 친구 선택 → 메시지/칩 → 캐릭터 응답
2. 장소 추천: 취향·제약 반영 → 장소 카드 제시 → 선택
3. 지도·출처: 선택 장소의 지도/주소/TourAPI 근거 표시
4. 호스트 학습: 스튜디오 A/B·동기화 → 게스트 추천 반영
5. 상태 확인: `/submit`에서 TourAPI·설정 상태 확인

### ② 기능 흐름도
게스트: 홈→캐릭터→채팅→(답칩)→장소카드→지도  
호스트: 스튜디오→친구/취향→TourAPI 동기화→게스트 반영

## 4. 데이터 활용(한국관광공사 OpenAPI)
활용 리스트:
- KorService2 / locationBasedList2 — 반경 내 음식점·관광지 목록
- KorService2 / searchKeyword2 — 키워드 검색 후보
- KorService2 / detailCommon2 — contentId 상세
- EngService2 / locationBasedList2 — 영문 병합(병행)
- (참고) JpnService2 — 미신청으로 403, 본 서비스 표시 범위 아님

## 5. [선택] 데이터 활용(기타)
해당 시: 없음(또는 LLM은 선택적 음성 생성용, 장소 사실의 근거는 TourAPI).

## 6. 서비스 차별성&발전계획
### ① 차별성
“평점”이 아니라 **누구의 취향으로 추천받느냐**. 추천 귀속(캐릭터/호스트)+공사 OpenAPI 장소 근거.

### ② 발전계획
단기: 답 품질·호스트 학습 루프·TourAPI 근거 UX 강화. 중기: 문화권 친구 확장, 호스텔 연동 추천·커머스.
