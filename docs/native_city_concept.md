# Native City — 콘셉트 & 전략 노트

> 신뢰받는 로컬 전문가의 **취향**을, 공개된 캐릭터형 AI로 전달하고, 추천을 실제 거래로 연결하는 여행·로컬 컨시어지.

---

## 1. 한 줄 정의

외국인 방문객(또는 인플루언서 팬)에게, 검증된 사람의 큐레이션된 취향을 **캐릭터 AI**로 전달하는 버티컬 유틸리티. 일반 챗봇이 아니라 "믿을 만한 현지 전문가" 경험.

## 2. 무엇이 아닌가 (포지셔닝)

- **Zeta 같은 컴패니언 앱이 아니다.** 그건 관계 자체가 제품(감정·파라소셜). 우리는 효용(문제 해결)이 제품.
- **ChatGPT 래퍼가 아니다.** 일반 컨센서스가 아니라 *특정 사람의 취향*을 전달하는 게 차별점.
- 핵심 trust 엔진:
  - **v1:** "너 같은 게스트들이 실제로 이렇게 했다" (호스텔 행동 데이터 = 사회적 증거)
  - **v2:** "롤린이 가르친 캐릭터가 그의 취향으로 추천한다" (인플루언서 보증)

## 3. 캐릭터 모델

- **AI임을 숨기지 않는다.** → Caryn식 "진짜인 줄 알았는데" 배신 절벽 제거.
- 형(rollinjoint)의 *복제*가 아니라, **"형이 만들고 가르친, 자기 정체성을 가진 별개 캐릭터"**.
  - 형을 흉내 내면 "진짜보다 못함"으로 평가됨 (복사기).
  - 별개 캐릭터면 (1) 독립적으로 평가받고 (2) 형이 안심(자기를 망신시킬 클론 아님) (3) 스코프 한정 가능.
- 선례: **K-아이돌 캐릭터 IP** (BT21 등). 멤버가 만든 별개 캐릭터가 그의 결을 품지만 독립 IP·굿즈로 큼. 아무도 진짜 사람인 척 안 시킴.
- → 이걸 "챗봇"이 아니라 **캐릭터 IP**(생김새·이름·성격·콘텐츠·굿즈, 그중 한 표면이 컨시어지)로 봐야 메타가 못 베낌.

## 4. 신뢰 아키텍처

- 캐릭터가 형 취향으로 **'안다'** (추천은 여기서 나옴) → 검색은 **검증 유틸리티** (아직 영업 중인지, 위치, 최신 정보 + 출처 표시).
- **핵심 규칙: 검증은 '사실'은 덮어쓰되 '취향'은 절대 못 덮어쓴다.**
  - "문 닫았어?" → 검색이 이김, 추천에서 제외.
  - "맛있어?" → 형 판단, 검색 리뷰는 투표권 없음.
  - (취향까지 검색이 덮으면 다시 컨센서스 집계기 = 해자 상실)

## 5. 핵심 난제 = 해자

- 진짜 어려운 건 채팅이 아니라 **"의견 추출"** — 형의 실제 미세 판단을 모델에 고충실도로 넣는 것.
- 어렵다 = 진입장벽 = 해자. 단, 주의: 모델 발전으로 이 추출-난이도의 **반감기가 불확실** (18개월 뒤 "영상 원클릭"으로 쉬워질 수 있음).
- **주의:** "형이 가르쳤다"는 *서사*(마케팅)와 *실제 구현*(엔지니어링)은 별개. 서사가 어려운 일을 한 것처럼 착각하면 안 됨. 추출 안 된 채 출시 = 형 이름 단 제네릭 답 = 최악(브랜드 깎고 해자 없음).

## 6. 가치는 어디에 있나

- **챗봇 자체엔 가치 적음** (AI 채팅 지불의향 낮음, 여행 episodic → 구독 약함).
- 진짜 가치 = **① 트랜잭션 레이어 + ② 복리로 쌓이는 자산**.
  - 고신뢰 추천 → 부킹/주문 → 커미션. 형 취향은 고전환 퍼널(콜드 검색보다 전환 훨씬 높음).
  - 추출·챗은 *입장권*, 상금은 거래하고 복리로 쌓이는 고신뢰 추천 퍼널을 *소유*하는 것.
- 규모: 단일 인플루언서 = 괜찮은 사업 / 플랫폼(누구 취향이든 변환하는 레일) = 큰 거(단, 양면시장 난이도 재등장).

## 7. 트랜잭션 레이어 (테이블링/선주문)

- 추천 → 즉시 줄서기 / 온라인 선주문으로 루프를 닫음.
- **킬러 피처(v1):** *자기 언어로 미리 주문* — 외국인이 한글 메뉴 못 읽는 문제 해결. 줄 스킵보다 클 수 있음.
- 효과: 추천이 실제 전환됐는지 **ground truth 데이터** 확보 = 해자 연료.
- 자산 재사용: 정 페스티벌용 줄서기/입장 시스템이 그대로 이 레이어.

**함정 & 결정:**

- **리스크:** 거래를 붙이면 *넓고 공짜인 추천 우주* vs *좁고 통합 필요한 거래 우주*가 분리됨. 그리고 형의 베스트(숨은 골목 맛집)가 정확히 디지털 줄서기/선주문을 안 가진 곳 → 통합 가능한 건 테크-레디한 덜 "취향"스러운 곳. 돈 버는 레이어에서 차별화 죽을 위험.
- 두 번째 회사 떠안기 (식당 어돕션은 캐치테이블·테이블링·네이버가 몇 년 쓴 일).
- **갈림길:** 직접 짓기(데이터=해자 소유, 어려움) vs 기존 거 붙이기(빠름, 데이터 넘겨줌).
- **페이징** (정 페스티벌 패턴 재사용): Phase 1 결제 없는 가벼운 오케스트레이션(줄서기/"갈게", 필요시 기존 예약에 딥링크해 전환만 캡처) → Phase 2 깊은 통합이 값할 데에서만 선주문+결제 소유.

## 8. 수익 모델

핵심: 거래 레이어에 꽂히지 말 것. 제일 쉬운 돈은 소비자 결제도 식당 거래도 아님 (각각 episodic 지불의향 / 공급 통합 문제). 그 둘을 우회하는 두 개가 근거리 수익.

**가장 쉽고 빠름 (여기부터):**

- **B2B 화이트라벨 (호스텔·호텔 SaaS):** 다른 숙소에 게스트 컨시어지로 라이선스. 사업자 정기 결제 → 소비자 지불의향·episodic 문제 통째 우회. 프론트데스크 부하↓·리뷰↑로 결제 이유 명확. 호스텔이 증명 케이스, 식당 공급망 불필요. → 제일 현실적인 근거리 수익.
- **여행 전체 어필리에이트:** 식당만이 아님 — eSIM·교통패스·공항픽업·투어·입장권·환전. 컨시어지가 여행 지출 한복판. Klook·Trip.com·eSIM 제휴는 이미 존재 → 공급 온보딩 0, 링크만. 거래 레이어의 "식당 통합 어려움" 함정 회피.

**거래 기반 (v2 / 공급 통합 필요):**

- 부킹·예약 커미션 (오픈테이블식: 커버당 or 식당 구독)
- 선주문 GMV 컷

**크리에이터 이코노미 (v2):**

- **레비뉴 셰어:** 플랫폼 컷 + 형 컷. 형은 롱테일 취향 수익화. 선불 안 받음 → 메타 무료와 비경쟁.
- **팬 구독(캐릭터별):** 슈퍼팬이 캐릭터 프리미엄(딥 액세스·독점 추천)에 결제. 패트리온식, 형과 분배.
- **캐릭터 IP 굿즈:** 챗봇이 가능케 하나 챗봇이 아닌 수익원.

**소비자 직접:**

- **트립 패스:** 월 구독 대신 여행 단위 마이크로 결제(예: 5일 서울 패스). episodic에 적합. 프로필 락인 쌓이면 빈번 여행자 구독도 가능.

**데이터 (해자 직접 수익화 — 스케일 후):**

- **수요 인사이트 판매:** "외국인 세그먼트 X가 실제 뭘 원하나"를 식당·F&B·관광기획에 익명화 판매. 딴 데서 못 사는 인텔. (프라이버시 주의, 스케일 선행)
- **관광공사·DMO·지자체:** 방문객 서비스로 기관 판매. KTO 공모전이 그 관계 입구.

**경고 — 신뢰와 충돌:** 식당이 돈 내고 추천에 오르는 **유료 노출·스폰서 추천**은 큐레이션을 썩혀 = Yelp+광고 = 해자 상실. 4번 신뢰 규칙의 돈 버전: **돈으로 '취향 레이어'를 못 산다.** 광고는 추천 *밖* 별도 슬롯만, 추천 자체엔 절대 불가.

**근거리 우선순위:** B2B 화이트라벨 + 여행 전체 어필리에이트 = 지금 당장 공급 통합 없이 수익. 거래·크리에이터·데이터는 나중에 얹기.

## 9. 해자 옵션 (스택됨, 배타 아님)

**복리로 쌓이는 것 (여기 베팅 — 네 자산에 박힘):**

| 해자 | 설명 | 비용 |
|---|---|---|
| 행동 데이터 플라이휠 | 호스텔 게스트 로그 독점, 쓸수록 좋아짐 (탭·저장·재방문만으로 신호) | 낮음 (순수 사용량) |
| 개인 프로필 락인 | "너를 안다"를 여행마다 누적 → episodic을 longitudinal로 | 낮음 (사용량) |
| 유통(호스텔) | 타겟 외국인이 필요한 순간 captive 유입 | 보유 자산 |
| 크리에이터 독점·관계 (v2) | 형 공식 캐릭터가 우리만 = 넷플릭스 독점작 | contingent (잡기 어려움) |
| 캐릭터 IP/브랜드 | 베낄 수 없는 사랑받는 IP | 호흡 긴 build |

**시간만 버는 것 (필수, but 영구 해자 아님):** 버티컬 깊이, 카운터-포지셔닝(거인이 안 건드림), 신뢰·검증. → 복리 자산 쌓일 동안 생존용. 자금 있는 경쟁자가 베낌.

**의사결정:** 거래 해자 = 제일 비쌈(2번째 회사). 데이터 플라이휠 + 프로필 락인 = 제일 자본효율적(식당 영업 0). → 첫 베팅으로 최적, 나중에 거래 얹기 안 막음.

## 10. 경쟁 지형

- **Meta AI Studio:** 크리에이터가 무료로 자기 AI 클론 챗봇을 만들어 인스타/메신저/왓츠앱에 배포. → "공개 AI 아바타" 포맷 자체는 해자 아님. 단 얕은 제네릭이고 데이터를 메타가 가져감. 우리 기회 = 깊이·버티컬·소유.
- **Caryn AI (경고 선례):** 최초 인플루언서 클론, 빠르게 수익. 창작자가 통제 상실(NSFW 드리프트)로 폐쇄. → 실명 페르소나엔 NSFW가 브랜드 폭탄. 공개+캐릭터화+책임 버퍼로 회피.
- **거래 인접 인커번트:** 캐치테이블·테이블링·네이버 (식당 네트워크 보유).

## 11. 로드맵 (한 길의 v1 → v2)

- **v1 — 호스텔 데이터 컨시어지** (= 관광공사 공모전 교두보): "전문가"가 호스텔 집단 지성. 사람 브랜드 리스크 없음, 데이터 소유, 드리프트 없음. 페르소나·튜닝·개인화 엔진을 안전하게 검증. 호스텔이 첫 "인플루언서"(veto 없고 데이터 내 것).
- **v2 — 인플루언서 캐릭터 플랫폼:** 검증된 레일에 실명 인간(형부터, 수요·공급 워밍업된 자산) 꽂기. 신규 조인 수동 튜닝 → 점점 자동.
- **원칙:** 엔진이 내 노드에서 돌기 전에 마켓플레이스부터 짓지 말 것.

## 12. 열린 질문 (형이랑 결정할 것)

- 어느 상금을 노리나? 단일 인플루언서(형) 사업 vs 멀티-크리에이터 플랫폼.
- 거래 레이어: 직접 짓기 vs 기존 거 붙이기.
- 책임 버퍼 다이얼: 형이 어디까지 자기 이름을 거는가.
- **"의견 추출"을 실제로 어떻게 할 것인가** (= 전체 성패의 핵심).
- 기존 사업(호스텔·PMS) 대비 자원·집중 배분.
